# Agent mode P0 (Worker) — 2026-10-31

Phase P0 of `docs/engineering/ai-agent-architecture.md`: the Luna Worker's existing
`POST /v1/responses` gained an agent mode (a body with `tools_version`). No new endpoint,
no iOS change. Contract: `backend/luna/README.md`; prompt and 12 strict tools:
`backend/luna/agent-v1.mjs`; probes: `backend/luna/agent_probe.py`. Synthetic data only
(`[QA]` titles, a fictional dentist event `t17`); no personal data.

  with `agent: {tools_versions: [v1], effort: low, max_steps: 6, daily_runs: 40}`.
- Offline tests: `npm test` in `backend/luna`, 9 tests (3 existing strict-mode tests unchanged).

## Method

Three receipts in the primary checkout's `tests/results/agent-p0-20261031/` (git-ignored):

| File | Path | Requests | SHA-256 |
| --- | --- | ---: | --- |
| `direct.jsonl` | OpenAI direct, local key | 14 | `41e03433d8e4303707d975f22d74642b02a0bf9a496469e09dda7aecd1c6fb51` |
| `replay.jsonl` | OpenAI direct, local key | 24 | `dfed640e4017914a9ddc99cd8235eaaae30d2b27dc443f85bb64ed3ab1bfafd9` |
| `replay2.jsonl` | OpenAI direct, local key | 7 | `288b5f4568260c631b26673d3c372f19a31fad12c7247ebfce5475f2bc05198b` |
| `worker.jsonl` | Deployed Worker, synthetic account | WORKER_COUNT | WORKER_SHA |

Direct requests use exactly the Worker's upstream body (same prompt, tools, `store:false`,
`include`) plus the one parameter under test (`text.format`, `service_tier`, or medium effort),
because the Worker deliberately refuses those keys. The key was read from the local `.env`
and never printed. `replay.jsonl` stepped once too early to find a reasoning item (step 1 had none),
so `replay2.jsonl` repeats the replay check by stepping until one appears.

The Worker probe signs in to one synthetic account. Registration was rate limited
(3/day/IP, used by earlier spikes), so the account `qa-agent-c3dda66ad445` was inserted
directly into D1 with the Worker's PBKDF2 format, signed in through `/auth/login`, and deleted
through `DELETE /auth/account` at the end (runs and calls removed with it).
