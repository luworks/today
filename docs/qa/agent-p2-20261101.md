# Agent P2 on a simulator — 2026-11-01

Phase P2 of `docs/engineering/ai-agent-architecture.md`: the on-phone agent loop behind the flag
`today.ai.agent` (default **off**; `-aiAgent` turns it on for one launch). Code: PR #263 (pure core:
`ModelClient`, `HostedLunaClient`, `ScriptedModelClient`, `AgentRunner`, `AgentReply`,
`AgentProposalBook`, `AgentHistory`) and the P2 wiring PR (`AgentPlannerTools` in One, Ask wiring in
`AskAgent.swift` / `AskView.swift`, `ChatThread.agentItemsData`, the flag). This file is the
simulator acceptance run against the **deployed** Luna Worker (contract unchanged, no redeploy).

## Setup

- Simulator **Today-AgentP2** (iOS 27.0, `668C5613-0BF8-42D2-9554-1E119974FB5B`), driven only through
  the T3 `agent-device` command (taps, typing, screenshots). `./dev build Debug --scheme TodayMock`
  and `simctl install` were used only to build and install; `simctl spawn … log stream` read the logs.
- App: TodayMock (Debug) with `-uiTesting -dataset /tmp/agent-p2/dataset.json -aiAgent`: an
  in-memory store, so every item below disappeared with the app process. The dataset is synthetic
  (`[QA]` titles, no personal data): reminder `[QA] 看牙医` tomorrow 14:00, `[QA] 取快递` today,
  event `[QA] 项目周会` tomorrow 10:00 with **3 synthetic attendees** (new optional dataset field
  `attendees`, reported by the test calendar service), event `[QA] 午餐` tomorrow 12:00.
- Luna: one synthetic account `qa-agentp2-971c1109` registered in Settings → Luna AI (random
  password kept only in a private temp file, never printed), cloud-upload consent on. Deleted at
  the end through the app's **Delete AI account** (`DELETE /auth/account`); D1 afterwards:
  0 `qa-agentp2-*` users, 0 orphan calls, 0 orphan runs.
- Metrics come from one `AGENT_RUN` log line per run (`AskAgentSession.logRun`): steps, cards,
  time to first card, total time, tokens and cost at the Worker's rates. Debug builds also log each
  `AGENT_TOOL` call with its arguments (simulator Debug builds only; synthetic data).
- Offline: the Simulator has no airplane mode, so case 7 launches with the debug-only
  `-agentOffline` argument, which points `HostedLunaClient` at an unreachable local port. The agent
  sees the same `URLError` → `.network` path as a phone without a connection.

## Bugs found and fixed (in the P2 wiring PR)

1. **A revision was reported as "没有改动任何内容".** `revise_proposal` updated the card but counted
   no card, so when the model's reply claimed a change, the code replacement said nothing changed.
   Revisions now count as a card on screen; the reply becomes "卡片准备好了，点了才会生效。"
2. **`find_items` missed a reminder the model filtered out.** For "牙医" the model passed
   `kinds: ["event"]`; the dentist is a reminder, so the run answered "没找到牙医预约". When the
   requested kinds have no match, the tool now returns matches of other kinds with a note.
3. **Undo of a calendar delete said "已撤销" without checking.** `ToolRegistry`'s event Undo
   returns nothing; the agent card now verifies that the event is back (or back at its old time
   for a move) and otherwise says Undo didn't go through. The run also showed that the TodayMock
   calendar fixture could not re-create a deleted linked event; the development fixture now
   behaves like EventKit (saving an unlinked copy creates a linked event).
4. **A decided change card shrank** to its footer's width; it now keeps the full width.
5. **The offline message promised too much** ("提醒、事件和闹钟仍可直接…"). With the agent on,
   only FastLane's clear reminders work offline; the copy now says so.

6. **`@Attribute(.externalStorage)` on the new `ChatThread.agentItemsData` blocked the in-place
   store migration** (`StoreUpgradeTests/baselineStorePreservesAllFieldsAcrossReopenAndMutation`:
   "Cannot migrate store in-place"). Found by the integration test, not the simulator; the field is
   now plain `Data` like its siblings and the test passes.

Not app bugs: two coordinate taps from the test harness landed on a card's Add / Apply because the
keyboard had moved the layout (one "买牛奶" was added and one edit applied by those taps). The run
switched to accessibility references for Send; the Activity ledger recorded both as approved taps.

## Known gaps (follow-ups, not P2 blockers)

- `propose_undo` answers `not_supported`; list / repeat / alarm on-off edits, deleting an Apple
  Calendar event that Today does not mirror, and whole-series changes are refused with a hint.
- Agent change cards live with the open chat, like the old change card: reopening the chat from
  the sidebar shows the text and the capture cards, and Undo of an applied change is then in Activity.
- With the flag on and no network, only FastLane's direct reminders work; §4.7 #3's offline
  previews for events and alarms still come from the old pipeline (flag off). Revisit with P4.
- Ask's "Add all" (pre-existing) adds every open capture card in the chat, not only its own batch.
  Agent creates are all `preview`, so §3 O2 still holds (confirmConsequence cards are change cards
  with their own button), but the button's scope should be its batch.
- Edits sometimes take two look-ups (5.8 s to the first card); O8's agenda snapshot is the P3
  candidate.
