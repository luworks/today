# Health dashboard: global order and read coverage

The Health sheet uses one user-controlled metric order. The sheet shows only the rows and one quiet Open Health link (owner decision, November 2026): no section heading or category labels, a date only when a reading isn't today's, and grey sparklines with only the latest reading in colour. Its ··· menu holds Manage Metrics and Browse Health Records. Manage Metrics uses the same shown order, then searchable hidden metrics; its Customize button exposes native SwiftUI List reordering, including automatic edge scrolling, and stopping a drag uses the native drop/cancel behavior. It also carries the read-only and "No data" explanation. Move Up, Move Down and Move to Top remain available on the sheet through accessibility actions and the context menu.

The saved `today.health.metrics` JSON array and all original metric identifiers remain unchanged. Existing arrays retain their stored order; the old display-only category sort is removed. Hide does not delete Apple Health data. Only metric selection/order is saved; values stay in memory. Dismissal commits management choices together. Refresh, foreground loading and read access changes never replace selection.

Read access to newly selected quantities is requested only after the management sheet closes. Browse Health Records exposes separate events, workouts, paired blood pressure and profile screens. Each screen explains its family and requires an explicit Read action before requesting access; completion never implies read permission. Empty results mean no readable data, which cannot distinguish absent data from limited read access. No write permission, Health writes, upload, clinical account connection or new entitlement is introduced.

The [public read coverage inventory](public-read-coverage.md) lists exact types, unit/aggregation rules, runtime availability and specialized unsupported families. Existing 7/30/90-day charts and 180-day comparison history remain. New sensor values are explicitly described as daily averages, cumulative types use HealthKit daily sums, low-frequency original readings retain individual samples, and nonnumeric events retain recorded categorical values/durations instead of fake sparklines.

Synthetic fixture coverage is documented in `tests/fixtures/health-dashboard-ui.json` and `health-records.json`. No claim is made that mocks validate HealthKit permissions, hardware measurements or physical-device behavior. Native acceptance evidence and remaining limitations are recorded with the delivery revision.

Numeric query errors use an optional `HealthQuerySource` capability, keeping the original `HealthSource` and `HealthService` signatures compatible. A thrown native query failure produces a retryable error, an empty successful query remains no-readable-data, and cancellation settles to existing content or idle without presenting an error. Per-metric generations reject old completions. The inherited void numeric authorization request cannot expose authorization-request errors through the legacy contract; request completion is never interpreted as read permission. The separate records request path throws observable request errors.
