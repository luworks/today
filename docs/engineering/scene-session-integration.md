## Root API changes

```swift
                  datasetURL: URL? = SceneSession.bundledDataset,

```

Delete every `SceneCatalogRuntime` / `.isolatedFeatures` / legacy prepare/dispose / `makeServices` / action-override reference in root-owned WorkbenchApp and Workbench assembly. Pass the validated configuration to the throwing session initializer directly. Retain one session while its scene is open, cancel/unmount its feature tasks, then call `dispose()` before replacing it. A session's service graph must never be reused after disposal. Reopening a scene constructs a fresh session; `.id(session.identity)` also prevents inherited view state when a host is reused.

Include the new Development file in both development executable source lists wherever membership is explicit. Both development executables need their existing TodayTestSupport and feature dependencies. Bundle `tests/fixtures/today-dataset.json` and the original `ios/One/cities.json`; local source-path fallbacks are development conveniences, not installed-app resources. Existing `Development/Support/TestDataset.swift` supplies only its versioned decoding structures; SceneSession performs fixture insertion itself to avoid the older loader's wall-clock `toggleDone` path. No required input is generated into `/tmp`.

Each session constructs its own nine-model in-memory container (OneTask, OneEvent, OneAlarm, OneList, Habit, ChatThread, LedgerEntry, AIGrant, ShareImportReceipt), unique disposable defaults domain, synchronized deterministic clock/UUID sequence and explicit calendar/locale. `PlannerTestServices` receives that exact container/defaults/runtime and opens its real memory ActivityStore. Its existing ActivityCenter, Ledger and PlannerActions remain the real implementation; actions, capture writes, list mutations, grants and Undo are not copied into the scene assembly. Fixture checklist/message/thread/alarm identities come from the session sequence. Operational session/defaults/export directory identity intentionally uses a fresh UUID, allowing simultaneous identical configurations without shared storage. Model constructors still have existing transient default values; fixture-owned timestamps and explicit identity fields are overwritten before save, without changing persistent declarations.

`host` installs only the required narrow actions, presentation, toast, Health models, UndoManager and standard SwiftUI date/locale/defaults environment values. It exposes no universal service environment. The same retained graph is passed to every feature constructor, real local editor, nested card editor, Search editor and detached sheet. Use `hostingController(rootView:)` for any UIKit-hosted feature root; constructing `UIHostingController` around an unwrapped feature bypasses required injection. The only UIKit controller constructed here is the local share controller or this explicitly wrapped hosting root. No EventKit controller/store, AlarmKit driver, location manager, audio engine, model session, OneStore or production service adapter is constructed.

## Features, fixtures and honest scenarios

The exhaustive catalog switch retains all 50 existing registry IDs and routes them to their actual feature pages, section views, editors or cards. No scene-level legacy capability gate remains. Root still owns SceneRegistry's explicit-DI capability declarations and scenario allowlist; SceneConfiguration validation remains authoritative. This lane does not invent universally supported scenarios or change saved registry handles.

- Normal uses the versioned planner dataset, a separate read-only external calendar fixture, three actual ledger creations, local timer/recents fixtures, the original city database, a stopped 5.75-second stopwatch and sample Health values. One unfinished reminder is explicitly linked to the local reminder driver so completion/receipt/Undo and failure paths are meaningful.
- Empty leaves models/timers/recents/cities/Activity empty. The named-reminder-list route keeps fixture lists while deleting all items. Empty Ask cards show no preview; no placeholder item is silently saved. Health empty answers remain empty, without claiming access denial.
- Dense inserts six copies of the versioned dataset at explicit minute offsets, retains 40 real Activity rows, multiple timer states, 12 city keys, eight stopwatch laps and all Health metrics. No production test flag is inspected by a feature constructor.
- Loading sets the local calendar query/readiness and reminder reconciliation state; Health queries use a cancellable 60-second delay and real HealthLoader timeouts. The speech fake stays locally listening. Local planner rows remain available while the external fixture is loading.
- Error sets calendar/reminder/timer errors and a linked reminder completion failure; Health uses the real timeout UI with a cancellable delayed response and a short model timeout. Ask's script returns an explanatory chat response and throws for editing plans. Failed capture insertion retains Add/status/references; native card feedback resolves a preview only when its returned `applied` flag permits it. This is fixture failure injection, not proof of spontaneous storage failure.
- Denied/revoked set local access/connection/notification/alarm capability state and reject linked completion. Speech reports denied, optional Ask routes report unavailable, and Health returns no data. Health never claims it can distinguish read denial from no samples. Revoked models the current lack of authorization; this assembly does not claim an OS authorization transition occurred.
- Unavailable disables Health availability, alarm availability and optional Ask/speech routes. Rule parsing remains available for explicit creation requests.

Only expose a scenario in the registry when the actual consumer can show the corresponding state. For example CalendarService has no error-display contract, and a fixed detail chart has no loading operation: setting a fixture flag alone is not evidence that either screen renders an error/loading UI. Parent integration owns the final applicable-state allowlist and functional checks.

Ask retains `SceneAskCapabilities`, a local `SceneSpeechDriver` and VoiceInput per session. `SceneAskCapabilities.agentModel` is a `ScriptedModelClient` per scenario (one local reply; a scripted failure for `.error`; unavailable for `.unavailable`/`.denied`/`.revoked`), so the Luna Worker is never called. Speech start/stop are local callbacks only. Scene close, added-capture, approved-plan, Settings-open and widget-rewrite callbacks have local inspectable outcomes rather than invoking system services. Add/Apply are still the only write triggers; acknowledgments and chat do not write.

Clock retains the same WorldClockStore/StopwatchModel across standalone and AlarmsView routes. Explicit initial seeds replace feature argument parsing. Sound uses the retained local preview driver. Alarm creation records through the real ledger. A development-only `scene.advanceClock` control on stopwatch/timer advances the owned clock; timer reconciliation uses an explicit local state projection so seeded legacy timers can advance without a live driver. This is deterministic simulation, not real elapsed-time or AlarmKit evidence.

Calendar local events use the actual EventEditor and real save/action/ledger dependencies. Non-native calendar source selection uses the actual CalendarsSheet service metadata. A system-event Search destination presents a meaningful read-only/unsupported message identifying the fixture, never a local replacement editor that pretends to edit Apple data. Native Calendar taps remain governed by the consumer's native-capability checks. Native EventKit acceptance is outside this session.

Settings receives controlled callbacks, the actual session ledger and reset through DataReset plus an explicit empty local inbox. Activity uses the real ActivityCenter/store and matching instance ledger flush/Undo/clear/export closures. Activity export chooses a unique URL under this session's export directory only after the explicit button tap, and shares the resulting real file. Dispose stops voice, invalidates Ask/cache, cancels toast, clears the local UndoManager, disposes services (ledger before Activity), stops the unstarted diagnostics object, removes only the session export directory and finally removes defaults.
